Task board — user stories & progress

Every user story derived from the requirements documents, tracked against five delivery stages. Progress is evidence-based: a stage counts as done only when the artefact exists in the repository. Verified is reserved for stories whose acceptance criteria are asserted by an automated test — manual browser checks count as Shipped, not Verified. Click any card for its acceptance criteria and current status.

Overall delivery progress
What changed in this update. The application was built and merged to main, so 47 of 51 stories advanced at least one stage. The four that did not are the three authentication stories and the reminder-delivery story.
  • 9 reached Verified — the calculation engine, cash projection, scenarios and localisation, all asserted by the 82-test suite.
  • 17 reached Shipped — screens that run in the app and were checked in a real browser across light, dark and mobile, but have no automated UI test.
  • Authentication is the bottleneck. The 11 stories still at Designed are mostly waiting on sign-in: without a signed-in user there is no row to write, so editing, confirming, exporting and reminders all stall behind it.
Why some stories did not move. A screen existing is not the same as a story being done. Where a card shows Prototyped rather than Shipped, the data is displayed and the logic works, but the story's core verb — edit, confirm, upload, export — is still a disabled control. 11 stories remain blocked on open questions; OQ-1 alone blocks the 7 ingestion stories and is still the single most valuable answer available.
